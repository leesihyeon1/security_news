# 심층 분석 실무 적합성 검토

검토일: 2026-09-24. 대상: 분석 워커, 조사 모듈, 최종 판단, 대응 산출물과 운영 최신 15건.

## 판단

현재 기능은 보안 뉴스의 조사 출발점과 공개 위협정보를 모으는 데 유용하다. 실제 조직의 사고를
확인하고 종결하는 분석가를 대신하기에는 부족하다. 공개 IOC·벤더 정보만으로는 사내 실행 여부,
영향 범위, 정상 업무와의 구분, 격리·복구 효과를 확인할 수 없다.

조사 수단은 이미 다양하다. urlscan, VirusTotal, NVD·KEV·EPSS, 패키지·확장 프로그램·GitHub,
교차 인텔, 인용 원문, 후속 조회가 있다. 이번 개선은 조회 서비스 추가보다 이미 수집한 정보를
판단에 제대로 전달하고 실행 가능한 대응 조건을 남기는 데 집중했다.

기준은 NIST SP 800-61 Rev.3의 탐지·대응·복구 흐름 및 CISA 사고 대응 플레이북이다.
증거 보존, 영향 범위, 통제 조건과 복구 검증은 서로 연결돼야 한다.

- [NIST SP 800-61 Rev.3](https://csrc.nist.gov/pubs/sp/800/61/r3/final)
- [CISA 사고·취약점 대응 플레이북](https://www.cisa.gov/sites/default/files/publications/Cybersecurity_Incident_Vulnerability_Response_Playbooks_508C.pdf)
- [Microsoft 고급 헌팅: 데이터·접근 권한·보존 범위](https://learn.microsoft.com/en-us/defender-xdr/advanced-hunting-overview)

## 운영 결과에서 확인한 문제

최신 15건을 읽기 전용으로 확인했다. 원문 수집 실패가 1건, 조사는 있었지만 종합 판단이 없는
사례가 1건이었다. 최종 대응 목록에는 완료 기준이 비어 있는 재료 기반 조치가 총 21개 붙어 있었다.
이 숫자는 전체 63건에 대한 품질 점수가 아니라 확인한 표본의 구조적 결함 수다.

| 사례 | 확인한 문제 | 실무 영향 |
| --- | --- | --- |
| CLOSEDQUORUM | YARA 결과 0건을 바이너리 부재로 보고 종결하는 안내 | 수집 누락·탐지 범위 밖의 샘플을 놓칠 수 있음 |
| GHAPPIER | 락파일 스캔 0건이면 종료, 블록체인 주소를 네트워크 차단 목록에 등록하도록 안내 | 실행 이력 누락과 통제 수단 불일치 |
| Gigabud | 검색 403 실패, 대응 계획 부재, Windows TVM 쿼리 중심 | 모바일 조사에 필요한 자료와 실행 경로가 부족함 |
| 여러 사례 | 정형 문장이 판단 조치 뒤에 완료 기준 없이 추가됨 | 우선순위와 실제 수행 조건이 불명확해짐 |

## 구현 개선

1. 조회 계획은 원문에서 지표를 보강한 뒤 한 번 결정하며, 선택한 순서대로 실행한다.
   조회 예외·사용 가능한 응답 없음·부분 응답·응답 수집을 구분해 기록한다. 원문 수집 실패도
   최종 판단에 전달한다.
2. 최종 판단에 교차 인텔·저장소·확장 프로그램·웹 검색 결과와 기사 원문을 전달한다.
   기존 AI 분석은 원문과 대조해야 하는 가설로 표시하고, 읽은 출처의 수집 시각을 저장한다.
3. 대응안에 담당 역할, 실행 조건, 로그·필드·기간, 증거 보존, 대체 방법, 완료 기준을 요구한다.
   추가 모델 호출 없이 기존 판단 호출을 사용한다. 기존 대응 카드의 설명과 완료 기준 영역으로
   전달해 화면 구성과 순서를 유지한다.
4. 조치의 `done`과 대안까지 근거 없는 지표를 검사한다. 0건만으로 종결하는 명시적 기준은
   종료 보류로 바꾸고 로그 수집 범위·보존 기간·센서·양성 테스트 확인을 요구한다.
5. 종합 대응안이 있으면 정형 재료 문장을 완료 기준 없는 조치로 추가하지 않는다. 판단이 없을
   때의 재료는 검토가 필요한 후보로 표시한다.
6. 템플릿 KQL에도 기본 형식 검사를 적용하고 필요한 테이블, 사내 실행 미검증 상태, 양성·0건
   해석과 대체 로그를 표시한다. 쿼리 형식 점검은 실제 실행·탐지 성능 보증이 아니다.
7. KEV 조회 실패를 미등재와 구분하고, 낮은 EPSS만으로 위험도를 낮추는 문구를 제거했다.
   이미 지난 KEV 기한은 경과로 표시한다. CVE가 없을 때 빈 패치 쿼리를 생성하지 않는다.
8. 후속 CVE 결과를 구조화된 취약점 데이터에 합치고 대응 재료를 다시 만든다. 패키지 후속 조회는
   npm·pip 생태계를 명시해야 하며 이름에 `@`가 없다는 이유로 pip를 선택하지 않는다.
9. 최종 산출물 점검을 후속 조회·차단 검토 뒤에 수행한다. 참고 링크만 있는 경우는 원문 확인으로,
   '차단 대상 없음' 같은 설명 문구는 실제 차단 산출물로 계산하지 않는다.

`scripts/check_analysis_quality.py`는 저장 결과의 구조적 완결성을 모델 호출 없이 확인한다.
`scripts/refresh_analysis_workflow.py`는 한 건의 판단 갱신본을 먼저 파일로 만든 뒤, 검토한 파일을
원본 백업과 동시 수정 확인을 거쳐 목록·캐시에 함께 반영한다. 준비와 반영을 나눠 모델 재호출을 피한다.

## 남은 한계와 다음 우선순위

- 사내 텔레메트리: SIEM·EDR·Entra·CMDB·CI 감사 로그가 연결되어 있지 않다. 현재 결과는
  수행할 조사안이며 내부 관측·격리·복구의 완료 기록이 아니다. 우선 읽기 전용으로 로그를 연결하고
  수집 범위·보존 기간·정상 이벤트 예제를 함께 검증하는 것이 효과가 크다.
- 사건별 근거 연결: 원문과 출처는 전달하지만 모든 주장에 문장 단위 인용·독립 출처·확신도를
  강제하는 구조는 아직 없다. 종합 기사나 일반 레지스트리 목록의 사건 귀속은 사람의 확인이 필요하다.
- 플랫폼 적합성: Android·iOS·클라우드·OT에는 MDE 중심 쿼리만으로 부족하다. 실제 사용하는
  MDM·MTD·클라우드 감사 로그에 맞는 플레이북과 테스트 자료가 필요하다.
- 탐지 검증: 형식 검사는 KQL 컴파일러가 아니며, 테이블·필드 존재와 탐지율·오탐률을 증명하지 않는다.
  테스트 환경에서 알려진 양성·음성 이벤트로 실행해야 한다.
- 실행과 사건 관리: 증거 보관·담당자 배정·처리 상태·재발 관측·사후 검토는 운영 시스템과 연결되어 있지 않다.
- 자동 검사는 완결성과 일부 명시적 오류만 찾는다. 모델의 의미적 오류·날짜 근거·공격 귀속을 전부 검증하지 못한다.

## 반영과 검증 범위

분석 워커와 판단 갱신 경로에 개선을 적용했다. 외부 서비스를 모킹한 테스트로 조회 순서·실패,
원문 전달, 후처리 이후 완결성, 대안 전달, 0건 종결 보류, 쿼리 검증 범위, KEV 조회 실패,
패키지 생태계, 원본 백업·캐시 보존·동시 수정 거부를 확인한다.

관련 회귀 테스트 60개가 통과했다. 대상은 `test_analyst_workflow.py`,
`test_analysis_grounding.py`, `test_common_utils.py`, `test_network_safety.py`이며
외부 조회와 모델 호출은 모킹했다. `git diff --check`도 통과했다.

운영 최근 15건의 추가 평가 명령은 실행 승인이 거절되어 실행하지 않았다. 이번 개선을 적용한
실제 모델 출력 비교와 기존 저장 결과 재생성은 수행하지 않았다. 기존 분석은 원래 기록으로 남는다.
대시보드 HTML·CSS·탭 순서는 변경하지 않았으며 Vercel 재빌드는 필요하지 않다.
