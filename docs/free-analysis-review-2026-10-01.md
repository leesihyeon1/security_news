# 무료 도구 기반 심층분석 개선 검토

검토일: 2026-10-01. 대상: 현재 작업 트리의 Python 심층분석 파이프라인.
범위: 코드, 기존 실행 로그, 설정의 비밀이 아닌 활성화 항목, 공식 문서 검토.
최초 검토에서는 분석 로직이나 모델 설정을 변경하지 않았다. 아래 구현 현황은 후속 작업을 반영한다. 신규 LLM 분석, 악성 사이트 방문, 샘플 실행은 하지 않았다.

## 후속 구현 현황

- 후속 검색으로 찾은 연구 원문을 최대 2건 읽어 출처와 수집 시각을 기록하고, 새 지표는 원문 문맥상 공격 관련 역할이 확인된 경우에만 제한적으로 추가 조회한다.
- 질문의 조사 기법을 사건명과 묶어 검색하고, 검색 0건을 자료 부재로 단정하지 않는다.
- 격리 브라우저 응답의 스크립트 특징과 본문 미관측 사유를 기록한다. 판단·패턴 입력에서 브라우저 증거를 앞에 배치하고 본문 특징만으로 실행이나 악성을 확정하지 않도록 지시했다.
- urlscan 검색 0건은 실재하지 않는 패턴이 아니라 적용 불가한 미검증 후보로 남긴다.
- 후속 원문, 정상 도메인 차단 제외, ClickFix 브라우저 증거 우선순위 및 0건 판정에 대한 오프라인 회귀 테스트를 추가했다.
- 분석 워커에 기본 분석·원문·조사 트랙의 비공개 체크포인트, 처리 중 작업 임대·만료 회수, 지연 재시도를 추가했다. 조회 입력이나 모델 설정이 바뀌면 체크포인트를 재사용하지 않는다.
- 질문별 증거 종류 검증, 두 개 이상의 확인된 유포지에서만 공통 HTTP 지문 승격, 정상 대조군의 패턴 제외, 저장 레코드용 오프라인 평가기(`scripts/analysis_evaluation.py`)를 추가했다.
- **남은 작업:** 실제 정상 페이지 음성 표본을 수집해 평가 데이터에 넣고, 실제 API·사이트를 이용한 표본 품질 측정을 운영 환경에서 수행하는 일. 현재 변경만으로 사람 분석가 수준의 판단이 입증된 것은 아니다.

## 결론

무료 서비스에는 조회 범위, 호출량, 응답 안정성의 제약이 있다. 그러나 현재 문제를 무료 모델의 추론 성능 탓으로만 설명할 근거는 없다. 모델 비교 실험은 하지 않았다.

코드에서 더 직접적으로 확인되는 병목은 다음과 같다.

1. 새로 얻은 자료를 다음 조사에 충분히 활용하지 못한다.
2. 브라우저에서 얻은 원문 대신 해시와 제한된 특징만 모델에 전달한다.
3. 목표 달성과 검색 결과 유무를 검증하는 기준이 약하다.
4. LLM 장애 때 조사 중간 결과를 이어서 처리하는 구조가 부족하다.

현재도 목표 기반 도구 선택, 질문별 상태, 후속 조회, 과거 분석 연결, IOC 역할 구분, HTTP 지문 추출, LLM 패턴 합성은 구현되어 있다. 따라서 이를 처음부터 다시 만드는 것이 아니라 기존 흐름의 끊긴 부분을 연결하는 것이 우선이다.

## 확인한 약점

### 1. 새 검색 결과를 찾고도 원문 조사로 이어지지 않음

- `scripts/investigation.py:1082`에서는 초기 검색 참고 링크의 원문을 추가로 최대 1개 읽는다.
- 그러나 `scripts/investigation.py:1208`의 후속 검색에서는 검색 요약과 링크를 병합할 뿐 새 링크의 본문을 다시 읽고 IOC를 추출하는 과정이 없다.
- 해당 반복에서 브라우저 재관찰, 패턴 재합성도 실행하지 않는다.
- `scripts/web_search.py:284`는 질문의 가장 긴 단어를 후속 검색어로 고른다. 사건명과 조사 목적을 함께 담는 의미 기반 질의가 아니다.
- 총 판단 라운드는 기본 2회다. 횟수를 늘리는 것만으로는 위 단절이 해결되지 않는다.

영향: 새로운 연구 보고서나 유포 경로를 찾더라도 요약 나열에서 멈추고, 그 안의 스크립트와 샘플을 실제 다음 조사 대상으로 삼지 못할 수 있다.

### 2. 브라우저는 연결됐지만 관찰 범위가 좁음

- `scripts/browser_research.py:83`의 실제 방문은 선택한 페이지 1개에서 첫 번째 유사 버튼 1개를 클릭하는 방식이다.
- 이동과 클릭 후 고정 800ms를 기다린다. 늦은 로딩이나 여러 단계 전환을 관찰할 충분한 조건이 아니다.
- DOM은 저장하는 대신 해시, 정규식 표식, 버튼명, 외부 스크립트 URL로 축약한다.
- 응답 본문은 `Content-Length`가 있고 512KB 이하인 경우만 검사한다. 길이 헤더가 없는 응답은 본문 특징 검사에서 빠진다.
- 본문을 검사해도 모델에 전달되는 것은 해시와 제한된 정규식 표식이다. 실제 스크립트의 관련 함수나 문자열 조립 과정을 읽는 기능과는 다르다.
- 현재 `.env`의 두 브라우저 플래그는 1이다. 다만 이 값 자체가 별도 VM 또는 네트워크 격리의 구현을 증명하지는 않는다.

영향: `filename:"jsrepo?rnd="` 같은 요청 형태의 추출은 가능하지만, 왜 그 요청이 유포 행위에 연결되는지와 어떤 부분이 변종에서도 유지되는지까지 설명하기 어렵다.

### 3. 확보한 증거가 최종 판단 입력에서 잘릴 수 있음

- `scripts/response_synth.py:200`은 지표와 샘플 관측을 먼저 붙인다.
- 개별 조회 결과 묶음은 900자, 전체 조회 재료는 앞의 9,000자로 제한한다.
- 샘플과 IOC가 많으면 뒤에 붙는 브라우저, 검색, 대응 관련 자료가 밀릴 수 있다.
- `scripts/pattern_synth.py:396`의 웹 관측 문자열도 9,000자에서 잘린다. 여러 시드와 과거 스캔이 앞부분을 차지하면 뒤의 라이브 브라우저 관측이 덜 전달될 수 있다.

영향: 도구가 조사하지 않은 경우와 조사했지만 모델이 해당 증거를 읽지 못한 경우가 섞인다. 한도를 무작정 늘리기보다 목표별 증거 선택이 필요하다.

### 4. 검색 부재를 사실 부재로 표현하는 부분

- `scripts/web_search.py:343` 이후는 검색 0건을 1차 분석이 아직 공개되지 않았다는 뜻으로 설명한다. 특정 검색 질의의 결과만으로 공개 자료의 부재를 증명할 수 없다.
- `scripts/pattern_synth.py:734`는 urlscan 0건을 실재하지 않는 패턴이라고 표현한다. 인덱스 범위, 시간, 쿼리 표현, 공개 여부의 한계도 가능하다.
- urlscan 패턴 검증은 검색 결과 상위 5건과 확인된 시드를 비교한다. 시드가 상위 결과에 없다는 사실은 미적중 증명이 아니다.
- 정상 페이지 음성 표본을 통한 오탐 검증은 없다. 현재는 미검증 표시를 유지하는 점은 적절하다.

영향: 조사 실패나 미관측을 부정적 사실로 오해하거나, 실제로 유효한 후보를 조기에 폐기할 수 있다.

### 5. 목표 완료 여부는 아직 문장 검증 중심

- `scripts/response_synth.py:469`는 질문 상태, 답, 근거 문구를 받으며 지어낸 구체값을 검사한다.
- 다만 해당 증거가 질문의 완료 조건을 충족하는지까지 기계적으로 확인하지는 않는다.
- 예를 들어 검색 건수는 유포지의 현재 악성 행위를 입증하지 않으며, 같은 호스팅 IP는 동일 캠페인을 확정하지 않는다.

영향: 근거 문장이 존재하는 것과 목표를 실제로 해결한 것이 혼동될 수 있다.

### 6. 무료 LLM 장애가 재시도 비용과 보고서 편차를 만듦

- 기존 `logs/analysis_worker_run_log.txt:4462` 부근에는 180초/120초 타임아웃, HTTP 504, 이슈 판단의 규칙 기반 복구가 연속으로 기록되어 있다.
- `.env`는 `LLM_PROVIDERS=nvidia`다. `scripts/common_utils.py:897`의 우선순위 규칙상 현재는 기본 NVIDIA/Ollama 폴백 목록을 사용하지 않는다.
- `scripts/analysis_worker.py:970`은 큐에서 먼저 꺼내 실행하고, 실패한 요청은 자동 반환하지 않는다. 기사 처리 중 프로세스가 중단되면 완료되지 않은 작업을 복구하기도 어렵다.
- 검토한 실행 경로에는 개별 도구 결과를 영속 저장하고 그 단계부터 재개하는 체크포인트가 없다. 완료 보고서 캐시나 상태 표시와는 다른 기능이다.

영향: 외부 조회를 마친 뒤 마지막 LLM 단계에서 실패해도 처음부터 비슷한 작업을 반복하기 쉽다. 단순 타임아웃 상향은 해결책이 아니다.

## 권장 변경 순서

### 1단계: 증거 전달과 재사용부터 개선

- 후속 검색 결과에서 목표와 관련성이 높은 새 문서만 읽고, 관측 시각과 출처를 붙여 IOC 및 행위 증거를 추출한다.
- 로컬 비공개 증거 저장소를 둔다. 우선 기존 Python과 SQLite/파일 저장으로 충분하며 별도 벡터 DB는 필수가 아니다.
- 원문/응답의 콘텐츠 해시, 출처 URL, 수집 시각, 증거 위치, 목표 ID를 저장한다. 문서와 과거 AI 판단을 구분한다.
- 질문별 증거 예산을 배분하고 잘린 항목을 기록한다. 모델이 필요한 증거의 다음 부분을 제한적으로 요청할 수 있게 한다.
- 검색 0건, 권한 제한, 호출 실패, 실제 반증을 구분한다. 실패 응답을 장기적인 부재 결과로 캐시하지 않는다.

### 2단계: 기존 반복을 목표 기반 다음 행동 선택으로 확장

기존 `LOOKUPS`와 `lookup_plan`을 유지하면서, 트랙 단위 아래에 허용된 세부 행동을 추가한다.

예: `문서 읽기`, `IOC 조회`, `특정 스크립트 읽기`, `관측 비교`, `검색 질의 시험`, `목표 판정`.

매 단계에서 모델은 목표 ID, 도구 이름, 검증 가능한 입력, 어떤 근거가 부족한지, 기대 관측을 짧은 JSON으로 제안한다. Python이 스키마, URL 범위, 쿼터, 중복 요청, 시간 예산을 검사한 뒤 실행한다. 임의 Python/셸 코드를 생성해서 실행하게 만들지 않는다.

목표 원장은 다음을 유지한다.

`목표 -> 가설 -> 필요한 증거 -> 실제 관측/반증 -> 상태 -> 다음 행동 -> 연결된 대응`

완료, 일부 확인, 반증, 외부 제한, 사내 확인 필요를 구분한다. 외부 공개 자료로 답할 수 없는 사내 감염 여부는 무한 재검색하지 않는다. 추가 재계획은 우선 1~2회로 제한하고, 총 호출량과 신규 증거 획득량을 함께 측정한다.

네이티브 도구 호출이 제한적인 모델이어도 현재처럼 JSON 출력과 Python 실행기를 분리하는 방식으로 구현 가능하다. 출력 형식이 맞는 것과 판단 품질이 좋은 것은 별도로 평가한다.

### 3단계: ClickFix와 탐지 패턴을 관측 비교로 검증

- 보관된 스캔부터 확인하고 필요한 경우에만 격리 브라우저를 사용한다. CAPTCHA 우회나 실제 명령 실행을 목표로 삼지 않는다.
- DOM/HTTP 원자료의 제한된 관련 구간을 비공개로 보관하고, 요청 시작 스크립트, 리다이렉트, 명령 복사, 다음 요청을 연결한다.
- 원문 문자열과 디코딩 결과를 구분한다. 정적 문자열 복원은 실행하지 않는 방식으로 수행하고 실행이 필요하면 별도 악성코드 분석 환경으로 분리한다.
- 관련된 여러 시드에서 같은 파일명, 쿼리 키, 응답 구조, 행위를 비교한다. 이미 있는 `resource_pivots`와 과거 스캔 비교를 확장한다.
- 알려진 양성 시드 포함 여부를 별도 제한 질의로 확인한다. 최신 결과 상위 몇 개에 포함되는지로 대체하지 않는다.
- 정상 CAPTCHA/광고/일반 스크립트 등 음성 표본에서 오탐을 확인한다. 양성 시드를 만드는 데 쓴 표본만으로 성능을 평가하지 않는다.
- 검색 패턴과 차단 룰은 별도 등급으로 둔다. Google dork도 후보 탐색용이며 결과 적중 자체를 악성 증명으로 사용하지 않는다.

예시 흐름:

`jsrepo?rnd= 요청 발견 -> 호출 스크립트/응답 확인 -> 가짜 인증 및 명령 복사와의 연결 확인 -> 다른 시드 대조 -> 정상 대조군 확인 -> 검색 패턴 제안 -> 사람 검토 후 적용`

이 과정을 통과하지 못하면 미검증 헌팅 후보로 남긴다. 특정 문자열 하나를 발견했다고 모든 적중 사이트를 악성으로 승격하지 않는다.

### 4단계: 단계별 재개와 호출 예산

- 작업을 완료 확인 가능한 처리 중 큐/임대 구조로 바꾸고, 수집과 목표별 조사 결과를 단계마다 저장한다.
- 일시 장애는 지수 백오프와 제공자별 쿼터를 따른다. 같은 대형 프롬프트를 즉시 여러 번 재전송하지 않는다.
- 실패한 목표만 재개하고 이미 수집한 문서와 HTTP 관측은 재사용한다.
- 긴 보고서 생성과 다음 행동 선택을 분리한다. 다음 행동은 짧은 구조화 응답으로 받고 최종 한국어 보고서는 마지막에 합성한다.
- Ollama는 코드 경로가 있지만 현재 활성화된 대체 경로가 아니다. 기존 장비의 성능과 실제 모델 품질을 확인한 뒤 선택한다. 로컬 모델은 API 과금이 없더라도 메모리, 전력, 처리시간 비용이 있다.

### 5단계: 실제 지적 사례로 회귀 평가

표현이 유창한지보다 증거 누락과 잘못된 대응을 측정한다. 저장된 원문과 가짜 API 응답을 이용한 오프라인 테스트부터 시작한다.

| 사례 | 통과 기준 |
| --- | --- |
| Lunex | 기사 근거에 있는 ClickFix, 보안 무력화, 자격증명 탈취를 조사 목표에서 누락하지 않음 |
| Twilio 사칭 npm | 정상 피해/정찰 대상 도메인을 악성 차단 목록으로 만들지 않음 |
| TerminalFix | 스크립트와 HTTP 근거에서 구조적 검색 후보를 설명하고 미검증/검증 범위를 명시 |
| 정보성 제품 기사 | 강제 IOC 조사나 무관한 MDE 쿼리 대신 배경과 확인 자료 제공 |
| 신규 문서가 후속 검색에서 등장 | 본문에서 얻은 새 해시/행위를 다음 조사에 연결 |

| 정상 CAPTCHA 및 일반 스크립트 | 클립보드/파일명 공통점만으로 악성 확정하지 않음 |

측정: 목표 누락률, 출처에 연결되는 결론 비율, 정상 IOC 오분류, 패턴의 표본 오탐/미탐, 분석 완료율, 재개 성공률, 기사당 호출량/지연시간. 숫자 목표와 개선 효과는 기준선을 만든 뒤 정한다. 현재 성능 향상률을 추정 수치로 제시하지 않는다.

## MCP 및 추가 도구 판단

MCP는 도구와 자료를 연결하는 규약이며 조사 전략을 대신 설계하는 엔진이 아니다. 공식 문서도 LLM 사용 방식이나 컨텍스트 관리를 규정하지 않는다고 설명한다. 따라서 현재 Python 도구를 MCP로 감싸기만 해서는 위의 병목이 사라지지 않는다. [MCP 구조 문서](https://modelcontextprotocol.io/docs/learn/architecture)

우선순위는 기존 Python 실행기에 목표/증거 상태와 세부 도구를 추가하는 것이다. 이후 브라우저 워커나 다른 분석 도구를 여러 클라이언트에서 공용으로 써야 할 때 MCP 어댑터를 붙인다. 당장 새로운 유료 서비스나 에이전트 프레임워크 전환은 필요하지 않다.

Playwright는 응답 본문과 네트워크 이벤트 관찰을 지원한다. 필요한 것은 라이브러리 교체보다 현재 저장/추출/비교 경로의 확장이다. [Playwright 네트워크 문서](https://playwright.dev/python/docs/network)

## 무료 서비스의 현실적 한계

- urlscan은 보관된 스캔을 검색하며 공개 범위와 계정별 호출 제한이 있다. 검색 0건으로 인터넷 전체의 부재를 판단할 수 없다. 민감한 URL을 공개 스캔에 자동 제출하지 않는다. [검색 문서](https://urlscan.io/docs/search/), [API 문서](https://urlscan.io/docs/api/)
- Brave는 응답 헤더로 남은 쿼터와 재시도 시점을 제공한다. 고정 sleep만 적용하기보다 해당 정보를 작업 예산에 반영하는 것이 좋다. [Brave 제한 문서](https://api-dashboard.search.brave.com/documentation/guides/rate-limiting)
- VirusTotal 공개 API에는 상업적 제품/서비스 및 신규 파일 기여 없는 업무 흐름 관련 이용 제한이 명시되어 있다. 무료 사용 가능과 조직 업무에 사용 가능은 다르므로 현재 계정 권한과 적용 조건을 확인해야 한다. [VirusTotal 공식 제한](https://docs.virustotal.com/reference/public-vs-premium-api)
- NVIDIA API Trial 약관은 시험 목적과 운영 사용을 구분한다. 현재 계정에 이 시험 약관이 적용된다면 운영용 무료 기반으로 전제할 수 없다. 적용되는 계정/서비스 계약을 확인해야 하며 이번 검토에서 계정 계약을 조회하지는 않았다. [NVIDIA Trial 약관](https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf)

유료 데이터에만 존재하는 비공개 텔레메트리와 샘플을 무료 코드 변경만으로 얻을 수는 없다. 그 경우에는 관측 범위를 표시하고 공개 자료 또는 적법하게 확보한 자체 관측으로 답할 수 있는 목표까지 완료해야 한다.
